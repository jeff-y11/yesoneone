# TASK-009: MCP Streamable HTTP Transport

## Goal
Move away from Server-Sent Events (SSE) for the MCP server and use streamable HTTP instead. The MCP transport should use streamable HTTP for all communication, eliminating the need for SSE connections.

## Requirements
1. **Replace SSE endpoint with streamable HTTP:**
   - Remove `/mcp/sse` SSE endpoint
   - Implement streamable HTTP endpoint at `/mcp/stream` 
   - All communication (tool discovery, execution, resource access) should go through this single HTTP endpoint using POST requests

2. **Key-based authentication (from TASK-008):**
   - Use the MCP key generation system from TASK-008 for authentication
   - Keys are generated by the system, user copies and pastes to partner site
   - Partner site uses the key for authentication via `Authorization: Bearer <key>` header
   - query parameter `key=<generated_key>` are NOT supported due to security concerns
   - Keys are masked (first 5 + last 5 characters) when displayed but full key used for auth

3. **Update MCP controller:**
   - Refactor `McpController.java` to use streamable HTTP pattern
   - All JSON-RPC 2.0 requests should be sent via POST to `/mcp/stream`
   - Support `tools/list`, `tools/call`, `resources/list`, `prompts/list` methods
   - Authenticate using Bearer key header

4. **Update WebSecurityConfig and Key service:**
   - Ensure all `/mcp/**` endpoints accept authentication via key (Bearer header)
   - Integrate with TASK-008 key service for key validation
   - Once the user of the key is identified, it should be added to the security context holder so that auditing can work.
   - Remove any JWT-specific authentication requirements

## Acceptance Criteria
- `/mcp/stream` endpoint accepts POST requests with JSON-RPC 2.0 bodies
- `tools/list` returns registered tools via streamable HTTP
- `tools/call` executes tools and returns results via streamable HTTP
- All MCP endpoints require `Authorization: Bearer <token>` header
- No token support via query parameters
